# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

## Готовое решение: запуск и тесты

Нужен **Node.js 20.11+** (для mock timers в тестах); проверено на Node.js 24.22.3.
Зависимостей нет, `npm install` не требуется. Команды из корня проекта:

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. В другом терминале:

```sh
node --test triage.test.mjs
```

### Поведение и проверка AI

- `server.mjs` проверяет вход до вызова AI. Битый JSON, отсутствующий `text`,
  нестроковое значение и строка из пробелов дают HTTP 400 / `invalid_input`.
- После вызова AI сервер разбирает JSON, проверяет тему по списку
  `delivery`, `pricing`, `other` и непустой строковый `draft` после `trim()`.
  Ответ собирается из разрешённых полей, дополнительные поля AI не копируются.
- Ожидание AI ограничено 300 мс через `Promise.race`; `AbortController`
  отменяет работу имитатора. Даже провайдер, игнорирующий сигнал, не блокирует API.
- Любой сбой AI даёт HTTP 200 и
  `{"status":"manual_review","topic":null,"draft":null}`.
  Это явный результат обработки заявки, требующей решения менеджера.
- `client.mjs` очищает тему и черновик при новой отправке. При сбое API,
  сети или разборе ответа показывает ручной разбор. Исходный текст остаётся
  в поле ввода. Браузер дополнительно ограничивает ожидание сети пятью секундами.
- Номер запроса защищает от устаревших ответов и ошибок; предыдущий fetch
  отменяется. Вставка результата через `textContent` не исполняет HTML модели.
- Имитатор `mock-ai.mjs` не изменён. Никакие ответы клиентам автоматически
  не отправляются; менеджер проверяет черновик и составляет ответ вручную при сбое.

### Что проверяют тесты

HTTP-тесты запускают настоящий сервер на свободном локальном порту:
невалидный ввод без обращения к AI, все допустимые темы, все пять меток сбоев,
неожиданные JSON-структуры, предельное ожидание и отмену, включая провайдера,
игнорирующего сигнал. Проверяется и раздача страницы/клиентского модуля.

Тесты интерфейса запускают настоящий обработчик формы на минимальном DOM-адаптере:
успех → сбой очищает старый результат, исходный текст сохраняется, пробельный ввод
не отправляется, более старые ответы и ошибки не меняют новый результат.
Отдельно проверяется браузерный таймаут с управляемыми часами.
Это автоматические тесты логики интерфейса; визуальный прогон в браузере не выполнялся.

Для ручной проверки в браузере: обычная заявка → `[error]` → `[timeout]` →
`[bad-json]` → `[bad-topic]` → `[empty-draft]` → пробелы.
При сбое тема и черновик должны быть пустыми, текст заявки — сохранённым.

### Польза менеджеру

Менеджер получает готовый черновик для обычной заявки и понятный переход к ручному
разбору при сбое, без риска использовать старый ответ. Эффект измеряем временем
ручной работы на заявку (включая проверку/исправления), долей черновиков без правок
и частотой ошибок на сопоставимых заявках до и после внедрения.

### Использование AI

Реализация, документация и тесты подготовлены с помощью OpenAI Codex в ChatGPT.
Автоматически выполнены HTTP-тесты и тесты обработчика формы; результаты проверены
по выводу тестового запуска. Ручная проверка кандидатом ещё требуется:
визуальный сценарий выше и просмотр кода перед сдачей.
